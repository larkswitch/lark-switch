# 2026-09-20 单账号凭据分叉

## 已确认的因果链

- 23:15 自动巡检 12 个账号正常；23:30 一个账号先校验失败，随后需要登录。
- 宿主该账号的凭据槽缺失，另外 11 个账号的槽与有效期正常。
- 同时，隔离执行环境仍有该账号的较新凭据，其签发时间对应 23:21，访问有效期至次日 01:21。
- 两个环境的静态宿主标记相同。旧检测错误地认为两边都可以直接运行官方 CLI。
- 对事故前最后一份快照进行单条恢复后，官方服务明确返回 refresh token 已被使用/吊销；停止尝试旧快照。
- 从隔离视图保全较新密文，只向宿主缺失的那一个槽写回，恢复前再次导出安全快照。随后用户身份核验、实际只读聊天列表 API、账号体检均成功。

这说明实际问题不是前端缓存，也不是整表被清空，而是两个凭据视图竞争使用一次性刷新凭据。Windows 静态标记相等只能说明读到了相同标记，不能说明后续凭据写入会落在相同位置。

## 修复

0.2.13 将 Windows 凭据操作集中到任务调度器启动的桌面宿主。普通桌面启动先转交任务；shim 与控制台通过宿主桥执行。桥接派生进程核对真实父进程、安装路径和自举参数；仅匹配注册表标记或伪造环境提示不能获得直连资格。协议版本同步提升并保留工作目录与显式标准输入，不自动回退到当前环境。

补充匹配标记但缺少宿主执行来源、伪造进程提示、协议工作目录与控制台目标的回归测试。账号校验保留脱敏失败原因；需要登录的账号使诊断报告失败，界面体检不再无条件显示成功。

## 恢复与防护边界

没有覆盖其他账号，没有整表回灌，没有把凭据提交到仓库。操作证据和加密快照只留本机。绕过受管入口直接调用官方二进制仍不受本控制平面保护；服务端撤销授权、过期或刷新响应丢失也不能被承诺永久自愈。
